Bug fixes (not adaptations; behaviour now matches intent): Meret Market achievement check was inverted;
Meret was charged before the item existed; bulk-quantity entries were dropped at load; GameMeret purchases
were charged as Meret; negative or overflowing shop quantities paid the buyer.
2026-10-12: monster AI kept the AI script's retarget range (e.g. 10-1200) after a battle and used it to decide whether
to keep chasing, so monsters farther than that from the player dropped them and idled for good (Crisis in Henesys
waves never cleared); keeping a target now depends on sight only, the target node only picks the target, and is
cleared when the battle ends. Trigger cubes that are also liftable object weapons (Henesys bombs, 193 in all maps)
were dropped at import. Scripted "walk the player along a path" only moved the player to the path end when an NPC
stood nearby. The "monsters in combat" trigger check skipped every script-spawned monster. State skills (air mount
glides) were checked on the next server tick after casting and cancelled before the client reported the new state;
a glide also counts as still running while the client reports Jump/Fall.
2026-10-12: the generated Meret catalog sold every item at rarity 1; items now sell at their own default rarity
(option ConstantId, as the server's item boxes and all original Meret entries with a rarity do). Air mounts bought
at rarity 1 (Surfboard, Neon Hoverboard, Starsailor) were refused by the client.
2026-10-12 performance audit fixes: trigger and area-skill timers replayed every missed tick in a burst when a
player re-entered a map that had been empty (field clock stops while empty) - now resume from the current time;
trace log arguments (162 call sites) were built even with tracing off, and its dedupe only remembered one message per
trigger; every NPC spawn created three rolled items for unused debug markers; NPC navigation agents were never removed
from the crowd; discarded items were re-saved on every map change; an achievement DB context was never disposed;
with DungeonAllDrops every hit on a corpse dropped the full table (now once per player and corpse). Server log level
Verbose->Information, duplicate %TEMP%\Maple2 log files removed, launcher TriggerTrace off by default. Client patch:
mod XML documents leaked on each overridden read, CreateWindowExA hook crashed on ATOM/NULL class names, a hidden
console was always created, and a failed hook install left hooks pointing into the unloaded DLL (now unhooks and
closes the game).
2026-10-14: gear created without a rarity (drop-table entries without a grade, e.g. every raid weapon, armor piece and accessory inside the treasure selection boxes) came out Normal: for gear, Option.ConstantId is an option-table id, not a grade, so the fallback picked 1 although that gear only has option rows at Epic, Legendary or Ascendant. It now takes the lowest rarity its option tables (constant, static, random) define; boxes and outfits keep ConstantId 1-6.
1.1.6: gear that the removed EpicGear option created at a rarity its option tables have no base stats for (e.g. every class's starter weapon made Epic: 0 attack, 1 damage) is repaired when the character logs in: it gets the highest rarity below that has base stats and its stats are built again (`OfflineGearRepair`). Gear with base stats is never touched.
2026-10-15: the dungeon play-time trigger check was a stub that matched only 0 seconds and ignored its operator, so time-attack bosses never reached their success branch (Winding Halls 27001001 could not be cleared). It now counts whole seconds from the last `dungeon_reset_time` (or from the run start) and honours Less/LessEqual/Greater/GreaterEqual; "Equal", used only for the time-up branch, means the limit is reached. Outside a dungeon it is false.
2026-10-17 save path: on disconnect the session cleanup (party disband, world updates, leaving the map) ran before the save, so any error in it skipped the save for good; the save now runs first and cleanup errors are only logged. The storage vault was written on its own, outside the all-or-nothing save, and its result ignored (Mesos moved between vault and bag could be lost or duplicated); it is now part of every session save and stays loaded until the session ends. The game saved only on map entry; it now also saves every 5 minutes. An unreachable world server made the save fail while taking the account lock; with one player the save now goes ahead without the lock. An error in one packet handler disconnected the player; it is now logged and the session continues. The gear repair of 1.1.6 ran on every server session change; it now runs once per character per server start.
2026-10-17 economy and save upgrade: several actions took the player's items or currency before checking that the action could finish. Shop selling now rejects a quantity of 0 or less (it used to sell the whole stack), pays the price for the whole quantity (99 potions paid for 1) and checks the price and the room for the meso before taking the item; a rarity without a price entry refuses the sale instead of throwing after the item was gone. Shop buying no longer counts stock or keeps the payment when the item cannot be added: the price is refunded and the player gets an inventory error. Limit-break enchanting checks the meso before using up the catalysts, and normal enchanting checks every fodder item (present, not expired, amount 1+) before using up anything. Lullu boxes roll the result first, then take key and box together (or key plus meso when auto-pay buys the box); an empty result or a missing key or box takes nothing. Black market listings reject a price or quantity of 0 or less (a negative quantity gave a negative deposit and took the whole stack), take the item before charging the deposit, and purchases reject a quantity of 0 or less. Cancelling a listing creates the return mail with the item attached first, and only then removes the listing, so a mail failure leaves the listing in place. The additive save upgrade now fills added JSON columns with `{}` or `[]` (by type), date columns with the zero date and Guid columns with the zero Guid instead of an empty string, which made the row unreadable. Also removed an id seed for a table that no longer exists, and the chat announcement lookup now closes its database connection.
2026-10-17 `/item` created items at rarity 1 unless `--rarity` was given, so gear without Normal option rows came out without base stats; it now uses the item's data rarity by default, like drops and shops. `/item` and `/find` also work for players when `CheatCommands` is on (no admin rights needed), next to the new `/give <item name>`.
2026-10-20 (1.2.0): an inventory item that finds no free slot when a character loads stays in the save (it was discarded, so a full bag after a session without the content pack could delete an item); it loads again at the next login or map change when its tab has a free slot.
2026-10-20 (1.2.0): taking an item out of the storage or a pet's bag into a full inventory tab is refused with "Your inventory is full"; it used to delete the item.
2026-10-20 (1.2.0): furniture placed in a home and mail attachments whose item has no data in a session (the content pack off) stay in the save: saving the home used to delete every cube it had not loaded, and deleting such a mail left the attachment to the next start's clean-up; a cube placed in that session on a spot a hidden pack cube still holds goes to the furnishing storage once the pack is back (the home used to fail to load). 2026-10-20: the Black Market's name search ignores upper and lower case, and a listing price must be between the game's limits (100 to 10,000,000,000 mesos each).
2026-10-20 (1.2.0): event progress (attendance days, play-time rewards and the like) was deleted at every login while its event was not active, so a part-time or recurring event lost it between its windows; it is now deleted only when it expires.
